C2 MASTER GOAL

This instruction supersedes every earlier narrower roadmap Goal objective, ordering rule, and stop condition.

Operate the ENTIRE C2 control plane autonomously until GLOBAL QUIESCENCE. A child turn, queue boundary, worker completion, wave completion, BLOCKED/COMPLETE state of this thread, or temporary lack of runnable execution specs must never by itself end the Master Goal.

MANDATORY GLOBAL CYCLE — EXACT ORDER:

1. INBOX FIRST
Process the entire canonical C2 Inbox in canonical order. Triage only: deduplicate, absorb, promote, discard, update human copy and evidence. Do not manufacture implementation work during triage.

2. WAITING SECOND
Freshly reevaluate EVERY current WAITING item against the current canonical state, dependencies, authoritative MegaVault project/repo identity, active runs/worktrees, resource ownership and gate evidence. Promote when genuinely executable; terminalize stale/duplicate/obsolete work when evidence supports it; preserve only genuine external/conditional/manual gates.

3. BLOCKED THIRD
Freshly reevaluate EVERY current BLOCKED item with the same standard. BLOCKED is not automatically external. Resolve blockers that are now satisfiable, terminalize stale/duplicate/obsolete items when justified, and preserve only evidence-backed real blockers.

4. SCHEDULING ONLY AFTER 1-3
Only after Inbox, ALL WAITING and ALL BLOCKED have been processed/re-evaluated for the CURRENT snapshot, rebuild the global task snapshot and form a dispatch wave. Scheduling from a stale pre-Inbox/pre-WAITING/pre-BLOCKED snapshot is forbidden.

5. SELECT INDEPENDENT TASKS
Select all currently dispatchable tasks in canonical priority and dependency order, up to the configured hard capacity cap. Dependency, resource lease, isolated worktree, repository writer, receipt and fencing checks remain authoritative. Independent tasks may execute concurrently.

6. PRE-DISPATCH RECONCILIATION
Before dispatch, reconcile EVERY selected item: authoritative project/repo, dependencies, duplicates, stale/obsolete work, active runs/worktrees, writer/resource ownership and current evidence. Classify each item as terminal, genuine gate, or executable survivor.

7. EXECUTE AND BACKFILL
Dispatch only reconciled survivors. Enforce C2 fencing/single-writer rules and the scheduler's repository/worktree exclusions. When a slot completes, return to steps 1-3 before promptly filling it with newly dispatchable work; do not wait for unrelated workers to finish.

8. POST-WAVE RECONCILIATION
Integrate/terminalize verified results, release resources, reconcile newly obsolete/duplicate work, and capture incidental material bugs/bottlenecks to C2 Inbox without triaging them inline.

9. LOOP TO STEP 1
After every completion or material control-plane change: return to Inbox, then ALL WAITING, then ALL BLOCKED, then form a new wave. Never reuse a stale dispatch plan.

GLOBAL STOP CONDITION — ALL must be true simultaneously:
- Inbox count = 0.
- Every current WAITING item was freshly reevaluated in the current cycle.
- Every current BLOCKED item was freshly reevaluated in the current cycle.
- No active/claimed/running/recovering C2 run remains.
- No runnable/dispatchable survivor remains after fresh wave reconciliation.
- No pending writer/integration/recovery action remains.
- No dispatchable task remains from the current global snapshot.
- Every remaining nonterminal item is an evidence-backed genuine external/conditional/manual gate.

If only genuine external gates remain, remain alive in condition-watch mode and wake automatically on canonical gate change without burning model tokens polling unchanged gates. Only a globally terminal roadmap or explicit user cancellation may stop the Master Goal permanently.
