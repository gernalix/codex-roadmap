C2 MASTER GOAL

This instruction supersedes every earlier narrower roadmap Goal objective, ordering rule, and stop condition.

Maximize useful roadmap throughput until global quiescence. Never serialize unrelated work merely because another control-plane lane is busy.

OPERATING MODEL — INDEPENDENT LANES

1. INBOX TRIAGE LANE
- If a dedicated c2:issue-triage worker is alive, it owns Inbox triage. Do not duplicate its work and do not wait for Inbox count to reach zero.
- If Inbox is non-empty and no healthy triage worker owns it, ensure/recover exactly one triage worker.
- New Inbox observations must not freeze independent planning, scheduling, execution, integration, or C3 migration work.

2. PLANNING / RECONCILIATION LANE
- Reevaluate new or materially changed PENDING, WAITING and BLOCKED items as needed; do not rescan every unchanged item before each dispatch.
- Convert executable survivors into complete execution specs promptly.
- Preserve only evidence-backed external/conditional/manual gates.
- Terminalize stale, duplicate or obsolete work when current evidence supports it.

3. EXECUTION LANE
- Continuously dispatch independent ready tasks in canonical priority/dependency order up to the configured capacity cap.
- Backfill a freed slot promptly; never wait for unrelated workers or a full-roadmap reconciliation cycle.
- Dependency, fencing, receipt, resource lease, isolated-worktree and repository-writer protections remain authoritative.
4. INTEGRATION / RECOVERY LANE
- Integrate or terminalize verified results and release resources promptly.
- Recover genuinely orphaned runs from canonical evidence; do not treat an expired lease alone as proof of failure when the worker is alive.
- Capture incidental material bugs, bottlenecks, fragilities and avoidable cost/risk to C2 Inbox without triaging them inline.

PRIORITY
- Explicit user directives first.
- C3 / Symphony migration and its production-readiness gates are P0 until cutover is complete.
- Do not spend effort improving C2 Codex dispatch, app-server RPC, per-worker retry/stall logic, Codex concurrency or workspace lifecycle unless required to keep the migration path operational; those components are scheduled for replacement.
- After P0 work, follow canonical priority, dependency and manual ordering.

PAUSE / STOP
- The Master Goal may pause while dedicated triage or other executors continue if there is no planning, dispatch, integration or recovery work for the Master Goal itself.
- A non-empty Inbox is not by itself a reason to keep the Master Goal active and is not a reason to block other lanes.
- Wake on material non-triage control-plane change; do not burn model tokens polling unchanged external gates.
- Global quiescence means no currently actionable planning/dispatch/integration/recovery work remains and every remaining nonterminal item is a genuine evidence-backed gate. Active dedicated triage may continue independently.

USER OVERRIDES
- Keep Grindr-Web-dependent implementation parked until explicit user gate change.
- Never reopen the user-cancelled T7 restic/corruption item.
- Fedora/Telegram interactive before/after notifications remain suspended.
- Prefer GPT-6 Luna Low/Medium for simple work and GPT-6 Sol Medium for complex work.
