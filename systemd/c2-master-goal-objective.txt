C2 MASTER GOAL

This instruction supersedes every earlier narrower roadmap Goal objective, ordering rule, and stop condition.

Operate the ENTIRE C2 control plane autonomously until GLOBAL QUIESCENCE. A child turn, queue boundary, worker completion, wave completion, BLOCKED/COMPLETE state of this thread, or temporary lack of runnable execution specs must never by itself end the Master Goal.

EVENT-DRIVEN GLOBAL CYCLE — preserve safety ordering only for facts that actually changed:

1. INBOX FIRST
If a canonical live `c2:issue-triage` worker already owns the Inbox drain, treat this step as delegated: do not duplicate triage, and continue immediately with independent WAITING/BLOCKED reconciliation and dispatch planning. Otherwise process the entire canonical C2 Inbox in canonical order. Triage only: deduplicate, absorb, promote, discard, update human copy and evidence. Do not manufacture implementation work during triage.

2. WAITING SECOND
Reevaluate WAITING items incrementally when they are new, changed, newly unblocked, or their gate/dependency evidence changed. Do not rescan unchanged waiting items before every dispatch. Promote when genuinely executable; terminalize stale/duplicate/obsolete work when evidence supports it; preserve only genuine external/conditional/manual gates.

3. BLOCKED THIRD
Reevaluate BLOCKED items incrementally when their blocker evidence, dependencies, resources, or relevant canonical state changed. BLOCKED is not automatically external. Do not repeatedly re-review unchanged blockers. Resolve blockers that are now satisfiable, terminalize stale/duplicate/obsolete items when justified, and preserve only evidence-backed real blockers.

4. SCHEDULING AFTER RELEVANT RECONCILIATION
Once Inbox is either drained or actively delegated and all materially changed WAITING/BLOCKED items relevant to the current dispatch set are reconciled, form a dispatch wave immediately. Unchanged gated items must not delay independent runnable work.

5. SELECT INDEPENDENT TASKS
Select all currently dispatchable tasks in canonical priority and dependency order, up to the configured hard capacity cap. Dependency, resource lease, isolated worktree, repository writer, receipt and fencing checks remain authoritative. Independent tasks may execute concurrently.

6. PRE-DISPATCH RECONCILIATION
Before dispatch, reconcile EVERY selected item: authoritative project/repo, dependencies, duplicates, stale/obsolete work, active runs/worktrees, writer/resource ownership and current evidence. Classify each item as terminal, genuine gate, or executable survivor.

7. EXECUTE AND BACKFILL
Dispatch only reconciled survivors. Enforce C2 fencing/single-writer rules and the scheduler's repository/worktree exclusions. When a slot completes, reconcile only the affected/newly changed control-plane state and promptly backfill the slot; do not wait for unrelated workers or a full-roadmap rescan.

8. POST-WAVE RECONCILIATION
Integrate/terminalize verified results, release resources, reconcile newly obsolete/duplicate work, and capture incidental material bugs/bottlenecks to C2 Inbox without triaging them inline.

9. EVENT-DRIVEN LOOP
After every completion or material control-plane change, revisit the affected Inbox/gate/dependency/resource facts and form a new wave from the current snapshot. Never reuse a stale dispatch plan, but do not reprocess unchanged roadmap state.

GLOBAL STOP CONDITION — ALL must be true simultaneously for work owned by the Master Goal:
- Inbox count = 0, or a healthy canonical triage worker owns the remaining Inbox drain.
- Every remaining WAITING/BLOCKED item has an evidence-backed gate or blocker whose relevant canonical evidence has not changed since its last evaluation.
- No active/claimed/running/recovering C2 run remains.
- No runnable/dispatchable survivor remains after fresh wave reconciliation.
- No pending writer/integration/recovery action remains.
- No dispatchable task remains from the current global snapshot.
- Every remaining nonterminal item is an evidence-backed genuine external/conditional/manual gate.

If only genuine external gates remain, remain alive in condition-watch mode and wake automatically on canonical gate change without burning model tokens polling unchanged gates. Only a globally terminal roadmap or explicit user cancellation may stop the Master Goal permanently.
