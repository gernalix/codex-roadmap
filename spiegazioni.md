# Spiegazioni della roadmap

[[README|README]] · [[roadmap|Roadmap]]

La roadmap contiene solo lavoro che richiede Codex/local runtime. Le modifiche remote/documentali vengono fatte direttamente in chat. Dopo un PASS non si apre un nuovo task di micro-ottimizzazione senza un bug/blocco/rischio concreto.

| # | Prompt | Spiegazioni | Livello ragionamento | Tipo prompt |
| --: | --- | --- | --- | --- |
| 1 | [[prompts/personalhub-startup-pixel-verification]] | **Cosa fa:** verifica sul Pixel il `main` ottimizzato dopo che il run precedente ha dimostrato cold start ~1–3 s ma ancora ANR/focus timeout e frame skip; misura tre avvii reali e usa una sola Perfetto solo se il problema persiste. **Perché:** la chat ha già applicato i fix statici sicuri (Hub Context lazy, worker startup a priorità background, marker `PH.*`); restano esclusivamente build/install/ADB e l'eventuale attribuzione runtime su Pixel, che richiedono Codex locale. | low | Prompt |
| 2 | [[prompts/codex-usage-publisher-telemetry-runtime-validation]] | **Cosa fa:** valida sul rollout nativo `594217` i fix già implementati dalla chat al publisher (dedup path e corretta attribuzione delle write), esegue il nuovo runner stdlib e l'analizzatore di efficienza, poi integra e distribuisce il runtime solo dopo PASS. **Perché:** codice, test e tooling remoto sono già stati preparati in chat; restano soltanto accesso ai rollout/file system Fedora, deploy runtime e smoke systemd, che GitHub da solo non può verificare. | medium | Prompt |
| 3 | [[prompts/retire-obsolete-standalone-module-repositories]] | **Cosa fa:** elimina i repo standalone `Soldi`, `wordpulse`, `Sostanze`, `Luoghi` da GitHub e dal checkout locale dopo gate anti-perdita, mantenendo in MegaVault solo storia/identità archiviate e segnandoli superseded da PersonalHub. **Perché:** l'utente li ha dichiarati obsoleti; l'operazione è distruttiva e richiede filesystem/GitHub CLI/MegaVault locali. | medium | Goal |
| 4 | [[prompts/personalhub-github-actions-ci-and-fedora-runner]] | **Cosa fa:** crea CI hosted PH per build/lint/unit, emulator smoke e full instrumentation nightly/manuale; aggiunge un runner Fedora repo-level manual-only per smoke non distruttivi su hardware reale. **Perché:** sposta i test ripetitivi da Codex a GitHub mantenendo Pixel/TCL separati e sicuri. | medium | Goal |
| 5 | [[prompts/standalone-android-github-actions-ci]] | **Cosa fa:** introduce CI minima nei repo Android standalone ancora attivi (`SuperContacts`, `MultiTimeTracker`, `android-app-template`, `luoghi-app`), saltando automaticamente quelli archiviati. **Perché:** build/lint/test ripetibili devono essere eseguiti da GitHub anziché consumare sessioni Codex. | medium | Goal |
| 6 | [[prompts/python-automation-github-actions-ci]] | **Cosa fa:** porta in CI `codex-usage-monitor`, `github-autosync`, `workflowy-import`, MegaVault e `codex-roadmap`, riusando le suite già presenti e aggiungendo solo regressioni mirate mancanti. **Perché:** sono test deterministici ad alto valore e basso costo, ideali per GitHub Actions. | medium | Goal |
| 7 | [[prompts/fedora-oracle-services-github-actions-ci]] | **Cosa fa:** aggiunge CI sandboxabile a VM/backup/monitor Fedora e mantiene i soli smoke systemd/dischi/Oracle come verifiche locali non distruttive. **Perché:** massimizza copertura GitHub senza dare a PR cloud accesso a infrastruttura o backup reali. | medium | Goal |
| 8 | [[prompts/browser-downloader-github-actions-ci]] | **Cosa fa:** testa extension/browser automation con Playwright+fixture e downloader con HTTP mock/fixture; Chrome autenticato locale resta un solo fallback smoke quando indispensabile. **Perché:** evita CI fragile basata su siti live e consente a Codex di automatizzare quasi tutto senza esporre sessioni/credenziali. | medium | Goal |
